# EU4 Linux版バイナリ解析・探索ガイド

EU4（Europa Universalis IV）のLinux環境における2バイト文字（日本語等）表示を目的とした、バイナリ解析およびフック箇所の探索ガイドです。

この作業は非常に難易度が高い「暗号解読」に近い工程ですが、GhidraやClineを併用することで、効率的に「テキスト処理ループ2」を特定することが可能です。

---

## 1. 背景知識：なぜ解析が困難なのか

商用ゲームであるEU4のバイナリは、解析を阻むいくつかの壁があります。

* **シンボルの不在（Stripped Binary）**: 関数名（例: `TextProcessing`）や変数名が削除されているため、画面上には `sub_7FF6C420` のような無機質なアドレスしか表示されません。
* **コンパイラの最適化（SSE/SIMD）**: 開発者が書いた「1文字ずつ処理するコード」は、コンパイラによって「8バイトまとめて読み込む」高速なコード（`movxsd` 命令など）に変換されています。
* **巨大なコード量**: 数百万行のコードから、たった一つのテキスト処理ループを探し出す必要があります。

---

## 2. やるべきこと（目的）

今回の探索のゴールは、**「テキスト処理ループ2」**と呼ばれる箇所を特定し、2バイト文字を正しく扱えるようにフック（処理の割り込み）をかける準備をすることです。

1. **「文字取得修正」箇所の特定**: 複数バイトをまとめてロードしている最適化コードを探します。
2. **アルゴリズムの癖の把握**: 1バイト単位ではなく、8バイト（64bit）や16バイト（128bit）単位でデータを扱っている箇所を特定します。
3. **フックポイントの選定**: 文字列の境界チェックやNull終端判定（`test al, al` など）を行っている付近が有力な候補となります。

---

## 3. GhidraのLinuxインストール方法

GhidraはNSA（アメリカ国家安全保障局）が開発した強力な静的解析ツールです。Java環境（JDK 17以降）が必要です。

### ステップ1：Java環境の準備

ターミナルで以下を実行し、JDKをインストールします。

```bash
sudo apt update
sudo apt install openjdk-17-jdk
```

### ステップ2：Ghidraのダウンロードと展開

1. [Ghidra公式リリース](https://github.com/NationalSecurityAgency/ghidra/releases)から最新のZIPファイルをダウンロードします。
2. 任意のディレクトリに解凍します。

```bash
unzip ghidra_xx.x.x_PUBLIC_xxxxxxx.zip -d ~/ghidra
```

### ステップ3：起動

解凍したフォルダ内の `ghidraRun` を実行します。

```bash
cd ~/ghidra/ghidra_xx.x.x_PUBLIC
./ghidraRun
```

## 4. Ghidraでの探索方法

効率的に「アタリ」をつけるための3つの戦略を紹介します。

### 戦略A：ユニークな「文字列」から逆引きする

ゲーム内で表示されるエラーメッセージや、設定ファイル名などを手がかりにします。

1. **Search -> For Strings**: `common/defines.lua` や `error.log` などの文字列を検索します。
2. **参照元（XREF）を辿る**: ヒットした文字列をダブルクリックし、その文字列を「参照している関数」へジャンプします。そこがテキスト処理関数の入り口である可能性が高いです。

### 戦略B：「形」でループ構造を探す（フローグラフ）

Ghidraの「Graph Control Flow」機能を使い、視覚的に構造を探します。

* **ループの重なり**: 矢印がグルグル回っているブロックが2つ重なっている場所（ループ2）を探します。
* **展開されたループ**: 異常に縦に長いブロックは、ループが最適化（Unrolling）されている証拠です。

### 戦略C：特定の命令とマジックナンバーで絞り込む

テキスト処理を高速化する際に使われる特徴的なコードを検索します。

1. **命令フィルタ**: `movxsd`、`movups`、`movdqu` といったSSE系命令が含まれている関数を探します。
2. **マジックナンバー検索**: Null終端を高速判定する `0x80808080` や、スペース `0x20`、改行 `0x0A` との比較（`CMP`）が行われている箇所を重点的に確認します。

## 5. 次のステップ：動的解析への移行

Ghidraで「怪しい関数のアドレス」を特定できたら、次は実際にLinux上でゲームを動かし、デバッガ（GDB）を使ってそのアドレスで処理が止まるかを確認する「動的解析」に移ります。

まずは、GhidraにEU4のバイナリを読み込ませ、**「Search -> For Strings」で `error.log` や `common/` といったキーワードを検索してみることから始めましょう。**
