# Translation body location and format check

Recorded 2026-11-21 (item 8). Question: where is the real translation
body in JSON format that the owner said exists in the environment
(under the user home, around Steam), and what is its key/value
format?

## Conclusion

No JSON-format translation body was found in the searched range.
The real translation body that exists in this environment is in
EU4 yml format, not JSON. The only JSON translation-shaped file is a
small test fixture in the repository itself (see below). Item 8
therefore closes with this negative result plus the yml body
identified; do not assume a JSON body is available for items 9-11.

## What the code and memory-bank expect

- `source/plugin/mod.d`: `loadTranslationMods()` reads only `.yml`
  files under the Paradox mod directory
  (`$HOME/.local/share/Paradox Interactive/Europa Universalis IV/mod`,
  depth search) into `translationMap` (localisation key -> Japanese
  value, UTF-8). No JSON loading code exists in the repository
  (no parseJSON / JSON translation loader in source, tests or
  memory-bank; "json" in memory-bank refers only to dub.json and
  launcher-settings.json).
- `memory-bank/03_development_guide.md` and the Makefile
  `deploy_translations` target: the deployed mod is generated by
  `submodules/EU4JPModAppendixI/main.py` (needs PARATRANZ_SECRET)
  into `source/localisation/*.yml`, then deployed as
  `eu4dll_translations`.
- `memory-bank/MANUAL-TEST.txt`: the manual-test translation path is
  also yml (`mod/jpmod_ap1_mod/localisation`).

## The real translation body found (yml)

Two identical copies were verified byte-identical for
`text_l_english.yml` (diff: SAME):

1. Deployed mod (the one the game / DLL actually loads for the
   user user):
   `~/.local/share/Paradox Interactive/Europa Universalis IV/mod/eu4dll_translations/localisation/`
   - 145 yml files, about 16 MB, 126,796 lines in total.
   - `.mod` file: `eu4dll_translations.mod`
     (name="EU4dll Japanese Translation", supported_version="1.37").
2. Generator output in the owner's own checkout (submodule
   initialised there, unlike the agent checkout where it is not):
   `~/git/EU4dll/submodules/EU4JPModAppendixI/source/localisation/`
   - `main.py` downloads a zip from Paratranz (project 76,
     `download_trans_zip_from_paratranz`), salvages the
     `localisation` folder from it, and applies
     `special_escape.py` encoding when assembling the mod.
     The salvaged/extracted files on disk (`extract/localisation/`,
     `source/localisation/`) are yml, not JSON.

Format of the yml body:

- UTF-8 with BOM, first line `l_english:`.
- One entry per line: ` KEY:N "Japanese text"` where N is the
  version suffix digit (0-9; the DLL loader normalises `:0`-`:9`).
- Keys are localisation keys; values are plain UTF-8 Japanese.
  No EU4dll escape bytes are present in the stored text:
  in `text_l_english.yml` (780,457 bytes) the count of bytes
  0x10-0x13 is 0. EU4 control markup (`§`, `$VAR$`, `£...£`) stays
  as UTF-8 text inside the values.
- Examples: `BACK:0 "戻る"` (diplomacy_l_english.yml:559),
  `CONNECT_TO_IP:0 "ID接続"` (EU4_l_english.yml:3056),
  `MENU_BAR_LOAD_GAME:0 "ロード"` and
  `MENU_BAR_QUIT:0 "ゲーム終了"` (EU4_l_english.yml),
  `MORALE:0 "士気"` (text_l_english.yml).
  So the `Back=戻る` pair used in earlier items does exist in the
  real data, keyed by `BACK`, with the plain UTF-8 value `戻る`.

## Implication for later items

- Items 9-11 should treat the yml body above as the translation
  source (the same source `translationMap` already loads), not a
  JSON file. Values are plain UTF-8, so the UTF-8-to-escape encoder
  in item 10 takes these yml values as input; no stored escape
  form exists to reuse.
- The deployed mod directory belongs to the user user; the
  agent user's own Paradox mod directory does not exist, which is
  why earlier runs observed `translationMap` with 0 entries.
