# EU4dll 開発 TODO

## 方針

Linux版EU4の文字列置換は、Ghidraによる静的解析を出発点にしない。
実行時の観測で文字列のロード・生成・受け渡し経路を絞り込み、必要な候補だけを静的解析する。

Windows版とLinux版は、同じフックアドレスや命令列を共有しない。
共有するのは翻訳辞書、置換ルール、ログ形式、検証項目とする。

FreeType/HarfBuzzを前提にしない。実機調査で利用が確認できるまで、これらへのフック実装は作らない。

## 現在確認済みの事実

- 対象はLinux x86-64版のEU4。
- EU4は動的リンクELFで、`SDL_*`シンボルを本体内に保持している。
- `SDL_Init`、`SDL_GL_SwapWindow`、`SDL_RenderCopy`などを確認済み。
- `libfreetype`、`libharfbuzz`への依存は確認できない。
- `FT_*`、`hb_*`シンボルは確認できない。
- OpenGLは利用しているが、描画APIは文字列置換の第一候補にしない。
- リポジトリには、LD_PRELOAD、AOBスキャン、`mprotect`、`ScopedPatch`、Linux向けパッチ処理がある。
- `make test`によるD言語ユニットテストがある。

## 観測結果（2026/08/22）

- `loadTranslationMods()` 完了時に `MENU_BAR_LOAD_GAME` だけを直接照会し、loaded/missing と値を1行記録する観測を追加した。
- `translationMap` のロードと既知キーの値はユニットテストで確認できる。これはゲーム本体の表示経路を確認するものではない。
- `LocalizeAddLocalization`、`YmlParse`、`PdxLocalize` 系、`CTextBox` の安全なLinux v1.37.5呼び出し境界は未確認であり、シンボルフックやインラインパッチは追加していない。
- `readelf -Ws` では上記候補シンボルの存在を確認した。これは実行時の呼び出し経路、引数、文字列形式を確認したものではない。
- `tools/trace_eu4_runtime.sh` はGDBブレークポイントのみを設定し、EU4本体へパッチを適用しない。実機でlocalisation読み込み経路の追跡結果を取得した。
- `runtime-trace.log`では表示時の `PdxLocalize` 実体や `CTextBox::ChangeTextBox` のヒットは確認できず、今回の短いTRACEでも `MENU_BAR_LOAD_GAME` との直接対応は未確定である。
- 前回の候補 `CTextBuffer::ChangeString()` / `CTextBox::ChangeString(CString const&)` は、`/tmp/eu4dll-candidate-trace.log`（9484 bytes）でTRACE 0件だった。GDB breakpointはそれぞれ `0x20d8c7e` / `0x20d3a9a` に設定できたが、今回の起動・操作では呼ばれず、表示経路は未確定のままである。
- 前回の表示更新候補は `CTextBox::UpdateTextSprite()` と `CTextBox::ChangeString(CString const&, FontFormatting, bool)` の2つに限定していた。前者は `CTextBox`内spriteへの仮想dispatch、後者は `CString` の比較・コピー後にsprite更新系dispatchを行う命令列を `objdump -dC` で確認した。
- 現在のGDB補助は新しい2候補のみを停止し、各ヒットで `symbol/tid/pc` の1行だけを出力する。既存のlocalisation読み込み300回ログと全レジスタ・バックトレース出力は廃止した。
- 新候補は `CTextSprite::SetText(...)`（`0x20d9da4`, 2151 bytes）と `CGraphics::CreateTextSprite(...)`（`0x2079b00`, 443 bytes）に更新した。前者は文字列を内部バッファへコピーしてフォント・テクスチャ処理と頂点再計算を行い、後者はスプライト生成後にテキスト設定の仮想関数へ引数を渡す。今回の実機TRACEでは前者442回、後者236回のヒットを確認したが、`MENU_BAR_LOAD_GAME`との直接対応、引数、文字列形式、寿命は未確認である。
- `CTextBox::UpdateTextSprite()` と `CTextBox::ChangeString(CString const&, FontFormatting, bool)` は、実機TRACE 0件のため候補から除外した。
- `MENU_BAR_LOAD_GAME` のASCII/UTF-8/UTF-16相当ポインタを安全に読める根拠は未確認のため、未確認アドレスの大量 `x/s` は実施していない。
- 未確認事項は、既知キーがゲーム内部で保持される形式、表示時の受け渡し関数、呼び出しスレッド、候補文字列のメモリアドレスである。
- 次に実機を再度止める必要がある場合も、候補2関数のTRACEで未確認ポインタを無条件に読む処理は追加せず、まず静的解析または安全な条件付き観測方法を検討する。全 `PdxLocalize` テンプレート一括フック、`open`/`read` フック、インラインパッチは行わない。
- `/proc/<pid>/maps` を利用する外部監視はGDBバッチスクリプトだけでは完結せず、現時点の置換候補絞り込みにも不可欠でないため追加しない。文字列一致が必要になった場合だけ、単一候補・単一ヒットの別プロセス監視を安全条件とともに再評価する。
